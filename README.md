# 週案エディタ

単一HTMLのReact参考実装。学級担任・専科の週案 / 行事カレンダー / 時数・年間指導計画を、ブラウザ内のデータで扱います。

- アプリ: `index.html`
- 現行設計: [docs/architecture-v4.md](docs/architecture-v4.md) / [学級・振替v3](docs/architecture-v3.md) / [共通仕様v2](docs/architecture-v2.md)
- 旧設計: [weekly_planner_design.md](weekly_planner_design.md)
- GAS: `gas/Code.gs`、`gas/appsscript.json`

## 起動

`index.html` をブラウザで開くか静的ホスティングで配信してください。React・Babel・SheetJS・フォントの初回取得にネット接続が必要です。通常版は週案と取り込みExcelをサーバーへ送りません。GAS版の行事同期とDrive保存は、利用者が明示的に有効化・認可した場合だけ行います。生のExcelファイルは送信しません。

## Excel

行事: 日付 / 行事名、または月 / 日 / 行事名の縦型表を指定します。横型の12か月表は「横型・月別ブロック」で月ごとに日列・行事列を指定します。1〜3月は選択年度の翌年です。

年間指導計画: 単元 / 配当時数 / 予定月の縦型表を指定します。シート・見出し・最終行・各列を選んでプレビューを確認してください。出版社固有の複雑なレイアウトを自動変換する機能はまだありません。

取り込んだ単元をコマ編集で指定し、授業後に「実施済み」にすると単元進捗へ反映されます。過去日付の計画は自動で実施扱いにしません。

「週操作 → Excel様式出力」で週案・時数報告のxlsxを出力できます。学校様式のxlsxを任意で選び、シート・差込セル・行列間隔を設定してください。設定は保存できますが、学校の原本ファイル自体は保存しません。数式への上書き・結合セルの左上以外の差込は拒否します。図形・マクロ・高度な書式の完全保持は保証しません。

## 保存

`weeklyPlan_v4` に全学級をまとめて保存します。旧 `weeklyPlan_v1` / `weeklyPlan_v2` / `weeklyPlan_v3` は原本を残して移行します。破損・未対応版は自動保存を止めて復旧案内を表示します。端末・ブラウザ・配信URLを変える前に設定からJSONを書き出してください。JSONにはメモも含まれるので、公開リポジトリには入れません。

## 専科・準備・振替・報告

1. 設定の担当区分を「専科教員」に変更し、学級設定で担当教科を選びます。
2. ヘッダーの「+」で学年・組・担当教科を登録し、学級選択で切り替えます。年度と学年は登録後に変更しません。新年度は新しい学級を追加します。
3. 「担当時間割」で全担当学級の授業と同時刻の重複を確認します。時数・単元進捗は選択学級の担当教科だけで計算します。
4. 「準備・振替」に持ち物一覧と準備チェックを表示します。中止授業の「振替候補」は、休業日・行事の対象限・他担当学級の授業を除いた未入力コマから選びます。学校の実際の時間割を確認して確定してください。
5. 「時数・指導計画」から「時数報告CSV」を開き、期間・基準日・学級範囲を選びます。月指定と年度全期間の報告に対応します。

中止は実施に数えません。振替先は「計画」として登録し、授業後に実施済みへ変更します。元の中止記録と振替参照は保持します。前週コピーは実施状態・中止理由・振替参照をリセットします。

## 追加の運用機能

1. ヘッダーの戻す/やり直すボタンで最大30操作を戻せます。学級切替は操作に数えません。入力欄外ではCtrl/Cmd+Z、Shift+Z/Yも利用できます。履歴は再読み込みで消えます。
2. 「週操作 → テンプレート」で通常週・短縮週・行事週などを保存し、空きコマのみ/週全体へ適用します。実施状態や私的メモは引き継ぎません。
3. 「週操作 → 一括実施確認」で実際に行った過去・当日の授業だけ選択して確定できます。
4. 「学校暦・予測」で授業数・校時・休業期間・短縮日を登録し、確認済みにします。学級ごとの通常時間割を指定すると、実施済み＋残りの条件付き見込から不足を表示します。空き枠への時間割反復は仮定であり、実績ではありません。祝日は自動追加しないので行事・休業を登録してください。
5. 「教室・移動」で教室・往復の所要時間を登録します。同時刻の教室利用と、連続する授業の移動時間不足を確認できます。他教員の予約は未入力なら検知できません。
6. 「年間比較」で4〜3月の単元配当と、同学年の担当学級別進捗を比較します。教材研究へ単元IDでリンクします。
7. コマ編集の振り返りを「振り返り」で年度・教科別に検索し、指定した翌年度等の単元の教材研究ノートへ転記できます。単元名が同じだけでは自動転記しません。

## GASで配信

1. `node scripts/build-gas.mjs` で `gas/Index.html` を生成します。
2. Apps Scriptプロジェクトに `Code.gs`、HTMLファイル `Index`、マニフェスト `appsscript.json` を反映します。
3. 最初は「アクセス: 自分のみ」「実行: アクセスしているユーザー」でテストします。校内共有はWorkspaceのドメイン制限を設定します。
4. 高度なGoogleサービスのDrive API v3を有効にします。標準Google Cloudプロジェクトを使う場合はCloud側でもDrive APIを有効にします。新しいデプロイからWebアプリを選び、Calendar・Drive・外部リクエスト権限を認可します。
5. GAS版の行事カレンダーに同期先カレンダーIDを指定して同期します。専用カレンダーを推奨します。

本リポジトリから本番GASへのデプロイは実施していません。利用者のプロジェクトID・アカウント・校内の公開範囲で設定する必要があります。`clasp` を利用する場合の `.clasp.json` はGit管理対象外です。

Googleカレンダー同期は作成・更新のみ。再送時は識別子がある行事を更新します。ローカルの削除や日付移動を含む双方向同期は次段階で実装します。

Driveは「同期・バックアップ」から本人用保存を有効にし、最初に手動保存します。既定では児童メモ・振り返り・教材研究ノート・タスクを除外し、含める場合は別確認します。学校の個人情報取扱規程を確認してください。「自動保存」は開いているGAS版の変更だけを3秒後に送信します。変更前の世代を10件保持し、revisionが異なる保存は拒否して自動送信を停止します。設定を戻しても過去のバックアップ内の私的情報は自動削除されません。

復元前に端末の原本を退避します。私的項目を除外した復元は、授業IDが一致する端末のメモだけを保持します。消えた授業のメモは復元前原本から回収してください。GAS版へ最初に移る場合は、通常版のJSONを設定画面で取り込みます。実行ユーザーを開発者に変更すると利用者分離の前提が崩れるので変更しないでください。

GASのiframeやブラウザ設定でlocalStorageが使えない場合は保存エラーを表示します。JSON書出を代替として残しています。

## 開発・検証

`node scripts/verify-core.mjs` で集計・日付・移行・操作履歴・Excel・GAS同期の39件を実行します。Playwrightが利用できる環境では `node scripts/verify-browser.mjs` と `node scripts/verify-v4-browser.mjs` を実行します。GASのブラウザ通信とDrive APIはテスト用モックで検証します。各出版社・学校の実ファイルとGoogle本番認可は別途検証が必要です。
