# 週案エディタ v2 詳細設計

更新日: 2026-10-03。実装の正本は単一 HTML の `index.html`。従来の `weekly_planner_design.md` は v1 の記録として残す。本書は v2 の実装契約であり、未実装を実装済みとして扱わない。

## 1. 精査結果と今回の範囲

旧実装の問題:

| 優先度 | 問題 | 改善 |
|---|---|---|
| 高 | 保存 JSON を無検証で描画し、`subjects.map` 等で白画面になる | 起動時の検証、旧形式移行、原本保持、起動エラー表示 |
| 高 | 全週を数え、年度・実施済みの区別がない | 日付から年度判定。計画 / 実施 / 中止を分離 |
| 高 | 生活が教科マスターにない。外国語と外国語活動が同一 ID | 生活・外国語活動を追加。3・4年の旧外国語は移行時に活動に変更 |
| 中 | 先頭シート・先頭行しか選べない。無効日付が繰り上がる | シート / 見出し行 / 列選択、厳密な日付検証、除外行の理由表示 |
| 中 | 再取込で行事が重複する | 日付・種別・名称の安定キーで重複排除 |
| 中 | 印刷時に `100vh` と `overflow:hidden` が残り内容が欠ける | 印刷専用タイトル・寸法・持ち物表示を用意 |
| 中 | 保存失敗を黙殺する。毎描画で読込を繰り返す | 一度だけ読込、保存失敗を表示、JSON バックアップ |

今回の実装: 週案、月間行事カレンダー、行事 Excel 列マッピング、年度・学年別時数、指導計画 Excel 列マッピング、単元 ID での実績比較、教材研究リンク、JSON バックアップ、ICS 出力、GAS 配信と明示的な行事同期の土台。

今回含めない: 全出版社の書式の自動判別、横型の12か月行事表の自動変換、Google との双方向同期、児童個人情報のクラウド保存、時数不足の自動解消、GAS 本番アカウントへのデプロイ。

## 2. データ契約

```ts
type DateKey = string; // YYYY-MM-DD。実在日付を検証
type SubjectId = string;
type LessonStatus = 'planned' | 'done' | 'cancelled';
type Plan = {
  version: 2;
  meta: { grade: 1|2|3|4|5|6; className: string; teacherName: string; schoolYear: number };
  subjects: Array<{ id: SubjectId; name: string; short: string; color: string }>;
  events: Record<DateKey, Array<{
    id: string; title: string; type: 'school'|'gakunen'|'holiday';
    source?: string;
  }>>;
  weeks: Record<DateKey, {
    weekStart: DateKey; // 月曜。キーと一致
    grade: number; // 作成時学年を保持。設定変更で過去実績を別学年にしない
    days: Record<DateKey, {
      gyozen: { text: string };
      periods: Record<'1'|'2'|'3'|'4'|'5'|'6', null | {
        subjectId: SubjectId;
        unit: string; sub: string; items: string; memo: string;
        status: LessonStatus;
        minutes: number; // 1..180。単位時間 = 分 / 45
        curriculumUnitId: string | null;
      }>;
    }>;
  }>;
  tasks: Array<{ id: string; text: string; date: DateKey; done: boolean; createdAt: number }>;
  curriculum: Array<{
    id: string; subjectId: SubjectId; grade: number; schoolYear: number;
    publisher: string; textbook: string; source: string;
    units: Array<{
      id: string; title: string; plannedHours: number;
      month: number | null; // 4..12,1..3。実施予定月。日付の推定はしない
      resources: Array<{ title: string; url: string }>; // http(s) URL のみ
    }>;
  }>;
};
```

ID は表示名から参照しない。改名してもコマ・教材研究リンクを保持する。年間指導計画は同年度・同学年・同教科につき1つを採用し、再取込は同じ名称・出現順の単元 ID とリンクを引き継ぐ。削除された単元を参照するコマは削除せず「単元の再指定が必要」と表示する。

## 3. 集計の定義

- 学校年度は4月1日から翌年3月31日。3月末・4月初めをまたぐ週も**各コマの日付**で分ける。
- 選択学年は `week.grade` と一致する週だけを対象にする。
- 年間計画時数 = `planned` と `done` の `minutes / 45` の合計。中止を除く。
- 実施時数 = `done` かつコマ日付が基準日・今日以前。日付が過ぎただけでは実施にしない。
- 年間達成率 = 実施 / 年間標準 × 100。表示は100%超も残す。バーだけ100%で上限。
- 標準までの残り = max(標準 - 実施, 0)。標準は最低時数の法的判定ではなく比較基準。
- 標準のない追加教科は別枠表示。標準のある教科だけで全体達成率を計算する。
- 単元進捗 = 単元 ID に紐づいた実施 / その単元の配当時数。名称の曖昧一致で自動集計しない。
- 基準月までの出版社配当時数を累積し実施と比較。「月末目安」として表示。月のない単元は進度差から除外し未設定件数を表示する。授業日・休業日が未登録の段階で正確な日単位の遅れを推定しない。
- 時数の到達と学習内容の定着は別指標。数値だけで授業の質を評価しない。

## 4. 画面と操作

- **週案**: 月〜金・行事・業前・1〜6限。教科のドラッグまたはタップで配置。コマ編集に実施状態・授業分数・指導計画単元を追加。前週コピーは新しい日付に置換し、実施 / 中止を計画に戻す。
- **行事カレンダー**: 月表示と日別行事リスト。手動追加・削除、Excel 取込、ICS 出力。GAS 内でのみ明示的な Google カレンダー同期ボタンを表示する。
- **時数・指導計画**: 基準日、年度・学年、教科別の標準 / 年間計画 / 実施 / 残り / 達成率。教科を選ぶと別表示の単元比較表。単元ごとに教材研究 URL を追加し、コマ編集から同じリンクを開ける。
- **設定・バックアップ**: 学年 / 年度 / 組 / 担任、JSON 書出・復元。学年変更で過去週の学年を変更しない。週案印刷は A4 横で1ページを基準とし、長文はコマで省略、編集画面で全文を確認できる。

## 5. Excel 取込フロー

ファイル → シート → 見出し行 → 列マッピング → 有効行・除外理由をプレビュー → 確定。

行事: 日付列または月・日列、行事名列、既定種別。`M/D` は設定年度の4〜12月 / 翌年1〜3月として解釈。Excel1900/1904日付システムを SheetJS で解釈する。Excel の架空日付1900-02-29、2/30、数式の未計算セルは取り込まない。日付を行間で引き継がない。

指導計画: 教科 / 学年 / 年度 / 出版社 / 教科書名と、単元名 / 配当時数 / 予定月の列を指定。単元名・月の結合セルは左上セルから補完するが、時数は補完しない。同じ名称が複数行にある場合も勝手に合算しない。合計行を除いた1行1単元の範囲を選ぶ。範囲・列が適合しないファイルは読み込みを確定しない。

現在の汎用取込は縦型の列マッピング。出版社によって形式や改訂版が違うため、後続開発は `parseCurriculumRows` の手前に出版社別アダプターを追加する。実ファイルを保存せず正規化したデータだけを保存し、出典・ファイル名を記録する。メーカー資料の自動転載・自動スクレイピングはしない。

出版社の例: [教育出版の年間指導計画・Excel提供ページ](https://www.kyoiku-shuppan.co.jp/tokushu/r6plan.html)。全社対応を名乗るには採用版ごとの実ファイル検証が必要。

## 6. 保存と復旧

キー: `weeklyPlan_v2`。v2がなければ `weeklyPlan_v1` を読み込んで移行する。v1原本は残す。状態は React state が正で、書込みは500msでまとめる。タブ終了前にも保存を試す。

JSON構文、版、配列、日付、参照、コマ状態を検証する。破損・未対応版は空表示に退避するが**保存を停止**し、保存済み原本のダウンロードと正常なJSON復元を案内する。勝手に消去しない。容量不足・アクセス拒否はエラー表示。ページのタブを閉じると失う状態を見えるようにする。

`loadPlan` / `savePlan` / `loadTasks` / `saveTasks` が保存境界。集計関数は副作用のない関数とする。同時タブ変更は通知して自動上書きを止める。次段階のクラウド保存では `revision` を用いた競合検知を必須にする。

## 7. GAS と Web アプリ

段階1: `HtmlService` で同じ単一HTMLを配信。Excel読込・週案・時数はブラウザで動かし、週案やメモをGASへ送らない。`gas/Code.gs` が `doGet()` を提供し、`scripts/build-gas.mjs` が `index.html` を `gas/Index.html` に複製する。

段階2: 利用者が同期ボタンを押したときだけ行事のID・日付・名称を `google.script.run` で送る。専用カレンダーIDを指定。利用者として実行し、カレンダー内のタグ付き行事だけを作成・更新する。再送は同じIDを更新し、他の予定は削除しない。ローカル削除をGoogleへ反映する双方向同期は未実装。

段階3: 別端末同期が必要なとき、本人のDrive/Sheets保存を追加する。これを選ぶと「完全端末内」ではなくなるので保存先を明示し、児童メモを同期対象に含めるかを別設定にする。Sheetsを唯一の正本にしない。GAS実行時間・クォータに備え、一括処理を小分けにする。

GAS公開は教育用Workspaceのアクセス制限と実行者を設定して行う。`ALLOWED`ドメインという文字列だけをクライアント側で判定して認可したことにしない。`XFrameOptionsMode.ALLOWALL` は必要がなければ使わない。

公式仕様: [GAS Webアプリ](https://developers.google.com/apps-script/guides/web?hl=ja)、[HTML Service制限](https://developers.google.com/apps-script/guides/html/restrictions?hl=ja)、[google.script.run](https://developers.google.com/apps-script/guides/html/communication?hl=ja)。GASのiframe・ブラウザ設定によってlocalStorageが使えない場合があるため、JSON保存の代替を残す。配信URLが変わると保存領域も変わり得るので移行前に書出す。

CDNとGoogle Fontsからライブラリ・フォントは取得する。週案JSONやExcelをCDNへ送る処理はないが、ネット接続自体がゼロではない。校内運用で完全オフラインにするなら依存資産をローカルに同梱する。

## 8. 優先度順の追加機能

1. **中止・振替の候補**: コマを消さず中止理由と移動元を保持。空きコマと期限から提案し確定は教師が行う。
2. **今週の準備一覧**: 持ち物・実験器具・印刷物・提出締切を週案からまとめる。児童名を含むメモは混ぜない。
3. **月末・年度末の時数報告CSV**: 集計条件と基準日を出力し、報告の再現性を保つ。
4. **学校暦・休業日・校時テンプレート**: 土曜授業、短縮日、夏休みを明示して残り授業可能時数を計算する。
5. **授業の振り返り**: 予定したねらいと実際の到達を別項目で記録し、翌年度の教材研究に引き継ぐ。
6. **通常週テンプレートと取り消し**: コピーと実施記録を混同しない。版履歴で誤操作を戻せるようにする。

## 9. 検証条件

- 新規・v1・破損JSON・型違い・CDN不通で白画面だけにならない。
- 6学年の標準合計が850/910/980/1015/1015/1015。
- 3月/4月の週、過年度、別学年、未来の実施、中止、30分授業を混ぜても実施集計が正しい。
- 実施済みの前週コピーが新週の実施時数を増やさない。
- Excel1900/1904、年なし日付、無効日付、複数シート、再取込重複、列未指定を検証する。
- 教科・単元ID一致だけで比較し、未紐付けの実施が見える。
- 教材リンクのjavascript/data URLを拒否する。
- PC/スマホ表示とA4横PDFを確認する。
- GAS同期は同一行事再送、失敗後再送、タグのない予定の保持をモックで検証。本番Googleでの認可・同期は別途必要。
